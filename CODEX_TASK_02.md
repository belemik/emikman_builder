# WDeaf Builder — Sprint 02 / Задание для Codex

Ты — Senior Frontend Engineer. Работаешь в **существующем локальном** проекте WDeaf Builder (React + TypeScript + Vite). Сначала изучи текущие исходники, package.json, структуру state, localStorage и JSON-схемы. **Не начинай новый проект и не переписывай приложение с нуля.**

## План работы (реализуй по порядку)

1. **Сохранить рабочую версию.** Создай отдельную ветку `feature/sprint-02-design-system-theme` (если используется Git и сейчас рабочее дерево чистое). Не уничтожай незакоммиченные правки. Не изменяй механизм авторизации.
2. **Обновить компонентный реестр.** Слить с существующим registry метаданные Select (`195:56257`), Checkbox (`50:320`), Table (`2071:1101`). Не дублировать Button и Input. Использовать `variantProps` для подтвержденных Figma вариантов и `editorProps` для пользовательского содержимого. Дополнительные пропсы не выдавать за свойства Figma.
3. **Предпросмотр Select и Checkbox.** Реализовать добавление на холст, выбор, изменение порядка, удаление и настройки в инспекторе. Рабочие состояния `checked/indeterminate`, `disabled`; `hover/pressed` — состояния preview, а не произвольные JSX props. Для Select `label` и `placeholder` являются **boolean вариантами**, а `labelText`, `placeholderText`, `optionsText` — контентом редактора.
4. **Предпросмотр Table.** В Figma найдено 14 вариантов `table-cell` (`cell-type`), 2 цвета ячеек и разделитель. Не изображай это как варианты корневого Table. Сделай Table композитным preview-паттерном: заголовок, шапка, минимум 3 строки на тестовых данных; таблица должна добавляться на Canvas и попадать в JSON/промпт. Можно добавить безопасное редактирование демонстрационных данных отдельно от Figma props, не писать backend.
5. **Токены.** Создать отдельный `tokens` модуль с токенами из `tokens.verified.seed.json`. Применить подтвержденные значения, не выдумывая отсутствующие. Важно: `spacing/radius/radius-4 = 4` — подтвержденный частный токен, а не дефолт всех компонентов. Реальная pixel-perfect геометрия не подтверждена.
6. **Theme Editor.** Добавить доступную пользователю панель настройки `primaryColor`, `radiusPx`, `fontFamily` с немедленным визуальным обновлением превью компонентов Canvas. Исходные токены immutable; изменения хранить в `themeOverrides`. Кнопки «Сбросить настройки» и «Восстановить WDeaf» (в базовый набор/отсутствие overrides). Цвет — HEX с валидацией; радиус — в разумном диапазоне 0–32px; шрифт — Manrope (по умолчанию) и системный fallback, если конкретные шрифты недоступны.
7. **Развести темы.** Существующая светлая/тёмная/системная тема приложения в профиле — это `appAppearance`, НЕ переопределения дизайн-токенов Canvas. Нельзя смешивать эти параметры и ломать профиль.
8. **Сохранение и миграция.** Не терять ранее созданные холсты Button/Input и данные авторизации. Обновить текущую схему JSON осторожно: если вводится новая schemaVersion — импортируй предыдущую v1, напиши миграцию. Импорт должен валидировать variant enum, boolean, размер данных; показывать понятные ошибки и не исполнять импортируемый текст/код.
9. **Генерация промпта.** Передавать компонентные IDs, порядок, `variantProps`, контент, использованные токены, `themeOverrides`, целевую платформу `web`, ссылку на Figma и правила соответствия. Явно разделять «Figma verified» и «Editor override». Не писать про точный экспорт токенов, pixel-perfect и Code Connect как о завершенном функционале.
10. **Проверки.** Запусти существующие тесты, `npm run build` и, если настроено, lint. Добавь или обнови тесты для восстановления старого документа, раунд-трипа Export/Import, настройки Theme Editor, генерации промпта и новых вариантов. В финальном ответе перечисли изменённые файлы, результат команд и что осталось приблизительным.

## Дизайн взаимодействия

- Слева библиотека из **5 компонентов**: Button, Input, Select, Checkbox, Table.
- В центре Canvas с выбором, добавлением, удалением, перестановкой и preview.
- Справа инспектор: `Свойства` / `Тема` (вкладки или режимы), не делать отдельное громоздкое окно.
- Редактор темы должен быть визуально понятен, повторять общий стиль работающего приложения и быть доступен с клавиатуры.
- Локальные overrides не должны менять оригинальную Figma и не должны делать сетевые запросы.
- Не подключать API-ключи, платные LLM, backend или облачную синхронизацию. AI-чат — следующий спринт.

## Критерии приёмки

- На холсте можно разместить все 5 видов элементов и изменить доступные props.
- Выбор другого варианта Select или Checkbox отражается в preview (насколько возможно без точных assets).
- Theme Editor изменяет цвет, радиус и шрифт предпросмотра сразу и хранит изменения после перезагрузки.
- Изменение темы Canvas НЕ переключает тему всего приложения в личном кабинете.
- Import/Export JSON сохраняет новые компоненты, настройки темы и работает с документами Sprint 01.
- Генерируемый промпт включает реальные имена Figma-параметров и указывает пользовательские overrides отдельно.
- Авторизация/профиль/выход не затронуты, существующие документы сохранены.
- Сборка успешно проходит; если нет — укажи ошибки и что именно осталось невыполненным.
