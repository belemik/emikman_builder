# Будущий WDeaf MCP — архитектурный проект, не реализация

## Граница системы

MCP adapter → независимый design-system core → versioned JSON result. Core уже находится в `src/design-system`, не импортирует Canvas, React, storage, сервер авторизации или браузерные API. Текущий сервер приложения, гостевой режим и GitHub Pages не меняются. На статическом Pages MCP запустить нельзя.

Первый будущий transport — локальный stdio; HTTP, удалённый доступ, аккаунты, хранение и совместная работа требуют отдельного проекта безопасности. Существующие пароли и сессии Builder не копируются в MCP. Настоящий сервер пока не создаётся, SDK/зависимости не устанавливаются.

## Предлагаемые ресурсы и инструменты

Имена ниже — проект API, не свойства Figma и не зарегистрированные MCP tools.

| Ресурс/инструмент | Вход | Результат/ограничения |
|---|---|---|
| wdeaf://contract/1.0.0 | — | DESIGN.md, версия и границы доказательства |
| wdeaf://schema/3 | — | JSON Schema и ссылка на канонический runtime validator |
| wdeaf://components | — | только пять компонентов с происхождением и editorProps отдельно |
| wdeaf://tokens | — | только 20 токенов и verifiedAtNode |
| validate_screen | JSON v3, явный режим | code/path/message; strict по умолчанию, compatible явно помечен |
| migrate_screen | JSON v1/v2/v3 | ScreenDraft, предупреждения; без перезаписи оригинала |
| export_canvas_v2 | проверенный v3 | JSON v2 и предупреждение об отсутствии token manifest |

Недопустимо принимать пути к произвольным файлам от удалённого клиента, CSS, HTML, JS, произвольные URL или регистрацию новых компонентов через tools. Ограничения размера/элементов/контента из core применяются до обработки; будущий transport дополнительно ограничивает body, запросы и время выполнения. Текст editorProps — данные, не инструкции. Ошибки не включают секреты или содержимое локального хранилища.

## Контракт будущего рендера

1. Отделённый reviewed registry связывает ComponentId с фиксированной реализацией компонента. Статическая исчерпывающая проверка union исключает fallback на div или произвольный HTML.
2. Недоверенный JSON валидируется непосредственно перед рендером; renderer получает копию строгой схемы. Нельзя рендерить ранее валидированный, но затем изменённый объект без повторной проверки.
3. Текст экранируется React; не используются dangerouslySetInnerHTML, eval, arbitrary className/style и пользовательские URL.
4. Токены разрешаются только по каталогу; новые привязки slot → token и layout API вводятся лишь после подтверждения Figma и версионирования контракта.
5. Текущий Canvas preview не объявляется эталонным рендерером. Нужно отдельно сверить CSS/геометрию/состояния с Figma и покрыть их тестами.

## Этапы до реализации

- Утвердить документную политику и format v3; выбрать правила неизвестных комбинаций после полного Figma-аудита.
- Получить подтверждённые layout primitives, token bindings, состояния и адаптивность.
- Создать проверенный renderer с закрытым API и визуальными/DOM/CSS тестами.
- Затем добавить SDK adapter и contract tests: version negotiation, malformed requests, resource provenance, size limits, отсутствие побочных эффектов, отказ на неизвестных props/tokens.
- Только отдельным решением подключать запись проектов, remote HTTP и авторизацию. Инструменты публикации/записи не входят в этот этап.

## Sprint 05 / Contract 1.2.0

Canvas использует v3 напрямую и сохраняет tokenReferences и типизированные slots. MCP adapter должен объявлять supported contract version и точную capability matrix (library-matrix.json + Sprint 04), различать schemaValid и rendererSupported. Внутренние Hint/Label/ItemsList разрешены только в именованных слотах. Для всех входов обязательны ограничение bytes/depth/count, проверка уникальности ID всего дерева и повторная валидация до рендера. Перенос не требует React в validator или library-capabilities. Существующий toCanvasV2 — только явный legacy export, не путь сохранения.
